🔀 Merge Sort

How It Works (Divide & Conquer)

  1. Divide (top-down, level by level): Level 0 is one node with the whole array. Each step splits every node into two halves — 1 node, then 2, then 4 — until every node holds a single value.
  2. Base case: A single value is already sorted — nothing to do.
  3. Merge (bottom-up, one node at a time): Combine each pair of sorted children with a two-pointer merge, working up to the root.

Key Insight: Merging two sorted halves is O(n), and there are O(log n) levels — total O(n log n), always.

MERGE-SORT(A, lo, hi):
    if lo == hi: return (base case, trivially sorted)
    mid = ⌊(lo + hi) / 2⌋ → divide into halves
    MERGE-SORT(A, lo, mid); MERGE-SORT(A, mid+1, hi)
    MERGE(A, lo, mid, hi) → combine two sorted halves
MERGE: compare fronts, take the smaller (two pointers)

Complexity Analysis

Time Complexity: O(n log n) — best, average, and worst (the two halves differ in size by at most one, whatever the input)

Space Complexity: O(n) — the classic merge uses a scratch array to hold the merged result

Stable: Yes — equal elements keep their relative order
