⚡ Quicksort

How It Works (Divide & Conquer)

This page shows the big picture: each partition locks one pivot into its final spot (green), then the left and right subarrays are sorted recursively — follow it all in the recursion tree below. Locked pivots keep their red PIVOT tag so they never disappear, and the tree shows each locked pivot between its two subproblems.

Partitions here use the Lomuto scheme (pivot = last element). For the comparison-by-comparison view of a single partition, see Partition (Lomuto) and Partition (Hoare).

QUICKSORT(A, lo, hi):
    if lo >= hi: return (base case / empty)
    p = PARTITION(A, lo, hi) → pivot to final spot
    QUICKSORT(A, lo, p−1); QUICKSORT(A, p+1, hi)
PARTITION: pivot = A[hi] (Lomuto, last element)
    scan: if A[j] ≤ pivot, swap it into the ≤ region
    swap pivot into place → return p

Complexity Analysis

  • Best/Average Case: O(n log n) — Balanced partitions
  • Worst Case: O(n²) — Bad pivots every time (e.g. sorted input, last-element pivot)
  • Space: O(log n) average — Recursion stack
  • Stable: No (standard implementation)
