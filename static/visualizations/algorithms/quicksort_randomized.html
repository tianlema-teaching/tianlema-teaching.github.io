🎲 Randomized Quicksort

Why Randomize?

Problem: Quicksort with a fixed first- or last-element pivot is O(n²) on sorted input (it always picks the worst pivot).

Solution: Pick a random pivot! This gives expected O(n log n) regardless of input order. Each Reset deals a fresh random array and fresh random pivots; press "Use Sorted Array" again for new pivots on sorted input. The recursion tree is usually far shallower than the 10-level chain (levels 0–9) that a fixed pivot gives on this sorted input, though an unlucky run can still be deep. Locked pivots keep their red PIVOT tag, and the tree shows each locked pivot between its two subproblems, so no value ever disappears.

Tip: use ← / → arrow keys (or Space) to step — no clicking needed.
Speed: 700ms
RANDOMIZED-QUICKSORT(A, lo, hi):
    if lo >= hi: return (base case / empty)
    pick random pivot, swap it to A[hi]
    p = PARTITION(A, lo, hi); recurse both sides
PARTITION: scan; if A[j] ≤ pivot swap forward
    swap pivot into place → return p

Complexity Analysis

  • Expected Time: O(n log n) — on any input, thanks to random pivots
  • Worst Case: O(n²) — still possible, but vanishingly unlikely
  • Space: O(log n) expected — Recursion stack
